# Sandboxed Agent Contract Validation

Validate the agent policy broker only against synthetic frozen evidence. Use a
dedicated namespace with Pod Security `restricted`, default-deny ingress and
egress, no service-account token, no host access, no privilege, no GPU, and no
external endpoint.

Run one positive fixture that emits reports/evidence only, then one negative
fixture containing a prohibited `command` argument. Required outcomes are:

```text
positive: status PASS, analysis_only true, reports_and_evidence_only true
negative: contract error: prohibited task arguments: command
```

For a real handoff, require a deterministic quality-gate PASS, create the
release manifest from the mounted foundation/tokenizer/adapter/contracts, and
run `verify-mounted-release` before generation. Preserve the model's first
invalid response as negative evidence; never rewrite it into compliance.

The positive fixture may then be a frozen response generated by that exact
accepted adapter. The broker must verify the real adapter digest and the full
typed plan. A live evidence packet must provide an explicit `reference_index`;
the broker rejects any finding, lock, authorization, query, or profile ID that
is not in that index. Tools are also limited by research selector, so a site
assessment cannot silently request an OCI or source-repository action. Run a
second fixture that adds a prohibited `command` argument and require the exact
rejection above. This validation still does not scan a container, repository,
site, cluster, or public endpoint and does not execute arbitrary shell commands.
